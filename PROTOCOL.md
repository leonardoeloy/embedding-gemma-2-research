# Preregistered exploratory protocol — 2026-10-11

Written before inspecting any benchmark score. This is a controlled diagnostic study, not a representative production benchmark or a new general theory of embeddings.

Question: when retrieving on-device deployment procedures, does topical semantic relevance imply satisfaction of hard requirements? Can structured prefiltering preserve relevant results that would be lost by filtering a short nearest-neighbor list?

Use three recent publicly downloadable embedding releases: Google EmbeddingGemma 2 (October 2026), Tencent WeMM-Embedding-2B (August/September 2026), Alibaba Ovis-Omni-Embedding-3B (September 2026). Pin immutable model revisions. Omni-Embed-Mini was considered but download required approval; it is excluded before any scoring. Text is a supported common modality for all three. No claims about image/audio/video are inferred from this text experiment.

Generate 12 topic worlds, six requirement families (negation, conjunction, numeric threshold, inclusive temporal interval, source/destination binding, semantic version ordering), two document representations (prose and fields), two requirement variants and three query paraphrases. Each cohort has eight candidates: four factual variants for the requested topic and four for another topic. Facts and text share one deterministic source. Candidate order is seeded and shuffled; all methods use the same order and stable tie rule. Queries use paraphrased task descriptions rather than exact document topic strings. In each cohort one control query asks only for topical relevance. Facts are fictional; these are not operational recommendations.

Primary outcome: constraint-satisfying relevant Hit@1 on all 864 constraint queries. Report topical Hit@1 separately to distinguish semantic failure from requirement failure. Also report MRR, relevant Hit@3, predicate violation@1, family/representation/paraphrase/variant breakdowns, and query-pair success (both opposing requirements correct). Since several families have multiple valid results, any relevant satisfying result counts; no preference for arbitrary variant IDs.

Baselines: seeded random ranking; BM25 lexical ranking; each model's native full-dimensional cosine ranking; same rankings with an exact structured predicate prefilter; and predicate filtering after top-1/top-3. Structured predicates and document facts are supplied by the synthetic dataset, as if an application's UI and catalog already provided them. This is an upper bound conditional on accurate metadata, NOT evidence that natural-language constraint extraction is solved. The predicate checks do not inspect relevance labels or topic IDs. Filtering leaves several candidates, including unrelated eligible procedures; semantic ranking still has work to do.

Run BF16 on one Intel GPU at a time, using exact FP32 normalized vector dot products for evaluation, no approximate index, quantization, finetuning, reranker, or custom optimization. Use model-native pooling and recommended retrieval formatting. Save every vector, score, ranking, raw prediction and runtime receipt. Check finite vectors, dimensions, norms and input lengths as basic measurement integrity. Use a simple sequential encoder with a small fixed batch; do not tune against scores. Any runtime fixes are documented. No unit/integration tests.

Secondary on-device question: apply supported Matryoshka truncation and renormalization to EmbeddingGemma 2 at 512/256/128 dimensions and WeMM at supported dimensions. Ovis needs a learned PCA/residual projection, so do not substitute naive prefix slicing. Report vector bytes independently of throughput or device memory: 4 × dimensions per FP32 document vector. Do not turn the ablation into a speed contest.

Uncertainty: 2,000 seeded bootstrap resamples of whole topic worlds, keeping each world's correlated paraphrases/representations/families together. Show descriptive 95% intervals, not population guarantees or formal model superiority claims. Freeze dataset and protocol hashes before model inference. Do not remove failures or edit data after seeing scores. If a dataset defect is found, retain the original data and results and version a correction explicitly.

Related work must be checked before claiming novelty. The intended contribution is a reproducible case study on very recent embedding models, a constraint-family diagnosis, and an on-device architecture decision (predicate prefilter versus short-list postfilter), not discovery that semantic search struggles with logic.
